### Diagnóstico, en este orden (con Chrome)

1. **Render** (dashboard.render.com → servicio de Knot)
   - Estado: tiene que decir *Live*. Si dice *Suspended* o *Deploy failed*, leer el motivo.
   - Logs: tiene que aparecer `[cron] tick HH:MM:SS` cada minuto. Buscar `Traceback`, `[error]`,
     `[whatsapp] envío rechazado`, `[config] no pude cargar`.
   - Environment: anotar qué variables existen (no copiar los valores secretos a ningún lado).
2. **Meta** (developers.facebook.com → My Apps → la app → WhatsApp → API Setup)
   - Número en *From* y su **Phone number ID**. Comparar con `WHATSAPP_PHONE_ID` de Render.
   - Si es un número de prueba, el número de Martin tiene que estar en la lista *To*.
   - Estado de la cuenta y del número en business.facebook.com → WhatsApp Manager (restricciones, calidad).
3. **Token**: el temporal de API Setup dura 24 h. `WHATSAPP_TOKEN` tiene que ser uno permanente de un
   Usuario del sistema (business.facebook.com → Configuración → Usuarios del sistema) con permisos
   `whatsapp_business_messaging` y `whatsapp_business_management`.
4. **Webhook** (WhatsApp → Configuration): URL = la del servicio en Render + `/webhook`; token de
   verificación = `WHATSAPP_VERIFY_TOKEN`; campo `messages` suscrito. Con cuenta nueva hay que
   configurarlo de nuevo.
5. **Prueba**: Martin manda "hola" y se miran los logs:
   - No aparece nada → Meta no avisa: webhook (paso 4) o número (paso 2).
   - `mensaje ignorado de un número no autorizado: ...XXXX` → `MY_WA_NUMBER` mal, o el número llega en un
     formato que `state.mismo_telefono` no reconoce. Salida rápida: `KNOT_SOLO_DUENO=0`. Después corregir
     la variable o la función (con su prueba en `tests/test_telefonos.py`).
   - `envío rechazado (401)` → token. `(400)` o `(404)` → Phone number ID o destinatario.

### Variables de entorno

| Variable | Para qué | Nota |
|---|---|---|
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID` | Enviar por WhatsApp | Sospechosas principales |
| `MY_WA_NUMBER` | Número de Martin, formato de envío (54 + característica + 15 + número) | Ahora también decide quién es atendido |

| `WHATSAPP_VERIFY_TOKEN` | Alta del webhook | Si falta usa un valor por defecto escrito en el código |
| `CRON_SECRET`, `LOCATION_SECRET` | Protegen `/cron` y `/location` | Si faltan, quedan abiertas |
| `NOTION_TOKEN`, `NOTION_DATABASE_ID`, `ANTHROPIC_API_KEY`, `GCAL_*`, `GROQ_API_KEY` | Notion, modelo, Google, audios | |

### Apagados de emergencia (variables en Render, sin tocar código)

- `KNOT_SOLO_DUENO=0` — atiende a cualquier número (como antes del 14/11).
- `KNOT_ROUTER=0` — vuelve al clasificador viejo en vez del agente de entrada.
- `KNOT_VERIFICAR=0` — apaga la relectura de Notion en las confirmaciones.
- `SONNET_MODEL`, `HAIKU_MODEL`, `SONNET_FALLBACK`, `HAIKU_FALLBACK` — cambiar de modelo.
- Volver atrás del todo: `git revert ada8009 8fc70d5` y push.
